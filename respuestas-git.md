# Respuestas Git

1. El add es como dejar preparado lo que quiero guardar, y el commit es el que lo guarda ya en el historial con su mensaje.

2. El push sube mis commits a GitHub. Te lo pueden rechazar si en GitHub hay cosas nuevas que tú no tienes en tu ordenador, así que antes tienes que traértelas.

3. El fetch solo mira y se baja lo que hay nuevo en GitHub sin tocar tus archivos. El pull se lo baja y además te lo mete en lo tuyo.

4. origin/main es lo que tengo guardado en local de la rama main de GitHub, tal cual estaba la última vez que hice fetch.

5. Antes del add el archivo sale como modificado en rojo, y después del add sale en verde en "cambios a ser confirmados", ya listo para el commit.

6. Te enseña los cambios que ya has preparado con el add, o sea lo que va a ir en el siguiente commit.

7. Sirve para ver qué commits hay en GitHub que yo todavía no tengo en mi copia.

8. Porque si son pequeños se entiende mejor qué has hecho en cada momento, y si algo falla es más fácil encontrar dónde fue.

9. Hice fetch para ver qué me faltaba, después un pull con --no-rebase para juntar lo del equipo 1 con lo mío, y ya pude hacer el push. No usé --force.
